# خدمة FastAPI للتعرف الضوئي على النصوص متعددة اللغات

**اللغة:** [中文](README.md) | [English](README_EN.md) | **العربية**

معمارية التعرف الدقيق متعدد اللغات المبنية على منطق خط إنتاج PaddleOCR PPStructure، تحقق التعرف عالي الدقة على النصوص متعددة اللغات من خلال الكشف الموحد للنصوص + التعرف متعدد اللغات + دمج الثقة.

## تصميم المعمارية

### المفهوم الأساسي
يعتمد هذا المشروع على منطق خط إنتاج PaddleOCR PPStructure، ويتبنى معمارية مبتكرة من "الكشف الموحد + التعرف الخاص باللغة + دمج الثقة":

1. **الكشف الموحد للنصوص**: استخدام نموذج كشف واحد لتحديد جميع مناطق النص (كتل النص) في الصورة
2. **التعرف المتوازي متعدد اللغات**: إرسال كل منطقة نص إلى نماذج التعرف المختلفة للغات للمعالجة
3. **دمج الثقة**: مقارنة درجات الثقة لنتائج التعرف متعدد اللغات لكل منطقة نص واختيار النتيجة المثلى
4. **دمج النتائج**: دمج نتائج التعرف المثلى لجميع مناطق النص في الإخراج النهائي

### المزايا التقنية
- 🎯 **التموضع الدقيق**: الكشف الموحد يضمن الاتساق والدقة في تموضع مناطق النص
- 🚀 **المعالجة المتوازية**: مهام التعرف متعدد اللغات تنفذ بشكل غير متزامن ومتوازي، مما يحسن كفاءة المعالجة بشكل كبير
- 🧠 **الدمج الذكي**: اختيار النتائج المبني على الثقة يختار تلقائياً أفضل نتائج التعرف
- 🌍 **مستقل عن اللغة**: لا حاجة لتحديد لغة النص مسبقاً، النظام يختار تلقائياً أفضل نتائج التعرف

## الميزات

- 🚀 **المعالجة المتوازية غير المتزامنة**: التعرف الضوئي المتزامن لعدة لغات، تحسين كفاءة المعالجة
- 🌍 **دعم متعدد اللغات**: يدعم الإنجليزية (en)، العربية (ar)، الفرنسية (fr)، ولغات أخرى
- 🎯 **التعرف الدقيق**: آلية اختيار النتائج الذكية المبنية على درجات الثقة
- 📊 **إخراج مفصل**: يوفر نتائج التعرف ومعلومات الثقة لكل لغة
- 🔄 **التحسين التلقائي**: يختار تلقائياً أفضل نتيجة تعرف لكل منطقة نص

## تفاصيل تكوين النماذج

تستخدم الخدمة ملف التكوين `default_confs/config.yaml`:

```yaml
detection:
  model_name: PP-OCRv3_mobile_det
recognition:
  fr:
    model_name: latin_PP-OCRv5_mobile_rec
  en:
    model_name: en_PP-OCRv5_mobile_rec
  ar:
    model_name: arabic_PP-OCRv3_mobile_rec
model_dir: models
```

### وصف وظائف النماذج

#### نموذج الكشف
- **النموذج**: `PP-OCRv3_mobile_det`
- **الوظيفة**: كشف موحد لجميع مناطق النص في الصورة وتوليد إحداثيات الصناديق المحيطة لكتل النص
- **الميزة**: يضمن أن جميع اللغات تستخدم نفس تموضع مناطق النص، تجنب نتائج الكشف غير المتسقة من نماذج اللغات المختلفة

#### نماذج التعرف
- **النموذج الفرنسي**: `latin_PP-OCRv5_mobile_rec` - محسن خصيصاً للتعرف على الأحرف اللاتينية
- **النموذج الإنجليزي**: `en_PP-OCRv5_mobile_rec` - نموذج التعرف المحسن للنص الإنجليزي
- **النموذج العربي**: `arabic_PP-OCRv3_mobile_rec` - متخصص للتعرف على النص العربي

كل نموذج تعرف محسن للغات محددة ويمكن أن يوفر أفضل أداء تعرف لتلك اللغة.

## تفاصيل سير العمل

### 1. معالجة الصورة المسبقة
- استقبال ملفات الصور المرفوعة
- التحقق من صيغة الملف والحجم
- توليد مسارات ملفات مؤقتة فريدة (باستخدام UUID لضمان التفرد)

### 2. مرحلة الكشف الموحد للنصوص
```
الصورة المدخلة → PP-OCRv3_mobile_det → إحداثيات مناطق النص (كتل النص)
```
- استخدام نموذج الكشف الموحد `PP-OCRv3_mobile_det` لتحديد جميع مناطق النص في الصورة
- توليد إحداثيات الصناديق المحيطة (bbox) لكل منطقة نص
- ضمان أن جميع مهام التعرف اللاحقة تستخدم نفس تموضع مناطق النص

### 3. مرحلة التعرف المتوازي متعدد اللغات
```
كل كتلة نص → [en_model, ar_model, fr_model] → نتائج التعرف متعدد اللغات
```
لكل منطقة نص مكتشفة، النظام سوف:
- يستدعي بشكل غير متزامن جميع نماذج التعرف للغات المكونة بالتوازي
- كل نموذج لغة يعالج نفس منطقة النص بشكل مستقل
- يولد نتائج تحتوي على النص المتعرف عليه ودرجات الثقة

### 4. مرحلة دمج الثقة
```python
# الخوارزمية الأساسية: find_best_words_from_groups
for each_text_block:
    candidates = [en_result, ar_result, fr_result]
    best_result = max(candidates, key=lambda x: x.confidence_score)
    final_results.append(best_result)
```
- مقارنة درجات الثقة لنتائج التعرف متعدد اللغات لكل منطقة نص
- اختيار تلقائي لنتيجة التعرف ذات أعلى درجة ثقة
- الاحتفاظ بنتائج التعرف من جميع اللغات للمرجع

### 5. دمج النتائج والإخراج
- دمج نتائج التعرف المثلى من جميع مناطق النص
- توليد إخراج كامل يحتوي على محتوى النص والإحداثيات ودرجات الثقة
- توفير معلومات ترتيب مفصلة لنتائج التعرف متعدد اللغات

## تحسين الأداء

1. **المعالجة المتوازية**: استخدام `ThreadPoolExecutor` و `asyncio` لتحقيق المعالجة المتوازية الحقيقية
2. **مجموعة الخيوط**: افتراضياً 4 خيوط عمل، قابلة للتعديل حسب تكوين الخادم
3. **الإدخال/الإخراج غير المتزامن**: جميع عمليات الشبكة غير متزامنة ولن تحجب الطلبات الأخرى

## تنسيق استجابة API

### هيكل الإخراج الرئيسي
```json
{
  "language": "en,ar,fr",                    // قائمة اللغات المتعرف عليها
  "bbox": {                                  // إحداثيات مناطق النص
    "0": [[x1,y1], [x2,y2], [x3,y3], [x4,y4]],
    "1": [[x1,y1], [x2,y2], [x3,y3], [x4,y4]]
  },
  "words_result": {                          // نتائج التعرف المثلى
    "0": "Hello World",
    "1": "مرحبا بالعالم"
  },
  "words_num": 24,                           // إجمالي عدد الأحرف
  "best_scores": [0.95, 0.87],             // أعلى ثقة لكل منطقة
  "combined_text": "Hello World مرحبا بالعالم", // النص المدمج
  "average_confidence": 0.91,                // متوسط الثقة
  "rank_reco_resp": [                        // نتائج التعرف متعدد اللغات المفصلة
    {
      "language": "en",
      "bbox": {...},
      "words_result": {...},
      "scores": [0.95, 0.82]
    },
    {
      "language": "ar", 
      "bbox": {...},
      "words_result": {...},
      "scores": [0.78, 0.87]
    }
  ]
}
```

### وصف حقول الاستجابة
- **language**: جميع اللغات المشاركة في التعرف
- **bbox**: إحداثيات الزوايا الأربع لكل منطقة نص
- **words_result**: نتائج التعرف المثلى بعد دمج الثقة
- **best_scores**: درجات الثقة للنتائج المختارة لكل منطقة نص
- **combined_text**: النتائج المدمجة لجميع النصوص المتعرف عليها
- **average_confidence**: متوسط الثقة الإجمالي للتعرف
- **rank_reco_resp**: يحتوي على نتائج التعرف المفصلة لجميع اللغات، يستخدم لتحليل النتائج وتصحيح الأخطاء

## اللغات المدعومة

اللغات المدعومة حالياً تعتمد على النماذج المكونة في `config.yaml`:

- `en`: الإنجليزية
- `ar`: العربية  
- `fr`: الفرنسية

يمكن توسيع دعم اللغات بإضافة المزيد من نماذج PaddleOCR.

## معالجة الأخطاء

- صيغ الملفات غير المدعومة ستعيد أخطاء 400
- اللغات غير المدعومة ستُشار إليها في الاستجابة
- استثناءات المعالجة ستعيد معلومات خطأ مفصلة

## توصيات النشر

### بيئة التطوير
```bash
# التنفيذ المباشر
python api_server.py

# أو استخدام uvicorn
uvicorn api_server:app --host 0.0.0.0 --port 80 --reload
```

### بيئة الإنتاج
```bash
# النشر متعدد العمليات (موصى به)
uvicorn api_server:app --host 0.0.0.0 --port 80 --workers 4

# استخدام gunicorn
gunicorn api_server:app -w 4 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:80
```

### توصيات تحسين الأداء
1. **عدد العمال**: يُوصى بتعيينه إلى 1-2x أنوية المعالج، مع مراعاة استخدام ذاكرة نماذج OCR
2. **إدارة الذاكرة**: كل عامل يحمل نماذج OCR كاملة، يتطلب ذاكرة كافية
3. **توزيع الحمولة**: يمكن نشر عدة مثيلات واستخدام موزعات الحمولة
4. **إدارة السجلات**: 
   - دوران ملفات السجل التلقائي (10MB/ملف، الاحتفاظ بـ 10 نسخ احتياطية)
   - السجلات مخزنة في دليل `logs/`
   - دعم مستويات سجل مختلفة

### نشر Docker
```dockerfile
FROM python:3.8-slim

WORKDIR /app
COPY requirements*.txt ./
RUN pip install -r requirements.nvidia.txt

COPY . .
EXPOSE 80

CMD ["uvicorn", "api_server:app", "--host", "0.0.0.0", "--port", "80", "--workers", "4"]
```
